# Feature: End-to-end tests with Playwright and axe

Feature 007, part 3. Unit and component tests (jsdom, MSW in node) cover the logic, but a few behaviours only exist in a real browser: native `<dialog>` and Escape, focus and tab order, `position: fixed` placement, virtual scrolling, the MSW service worker, real viewport widths. This feature adds a small, deliberate end-to-end suite for exactly those, plus axe on every screen in a real browser at 375 and 1280 px. It is not a second copy of the existing tests.

Depends on: `007_01-role-pass-spec.md` and `007_02-disabled-reason-spec.md` merged (their notes name the first scenarios: Escape in a native dialog, two reasons open at once), all screen features merged, `docs/adr/0004-clerk-permissions.md`, `002_03-app-shell-spec.md` (role switcher, `?mock=` scenarios).

Read first: `context/coding-standards.md` (Accessibility, Testing), `current-feature.md` notes of `007_01` and `007_02` (the "E2E candidate" and "Known limitation" lines), `apps/web/src/mocks/` (how the service worker starts in the browser and how `?mock=` and `X-User-Id` work), `apps/web/package.json` and the root `package.json` scripts, `.gitignore`.

## Goals

### Setup (ask before installing)

- [ ] The plan lists exactly what must be added (expected: `@playwright/test` and `@axe-core/playwright` as dev dependencies of `apps/web`, and the Chromium browser binary) with the reason for each, and **stops for approval before installing anything**. No other library.
- [ ] Chromium only. Projects (or equivalent) for two viewports: 375 px wide (mobile) and 1280 px wide (desktop).
- [ ] `playwright.config.ts` starts the app with `webServer` from a production build served locally (`vite preview`), because the suite must run against the same MSW setup the deployed demo will use. The plan states how the service worker starts there and fixes it if it only works in dev. `baseURL` set, `reuseExistingServer` only outside CI, traces on first retry, no video by default.
- [ ] Scripts: `pnpm e2e` runs the suite; it is **not** part of `pnpm test`, so the existing gate stays fast. Reports and traces are git-ignored. A short "Running e2e" section is added to the repo's contributing or testing notes (where the plan finds the right place), including the one-time browser install command.
- [ ] Tests are independent: every test starts from a fresh store (reload or a reset hook the plan names), none depends on another's data, no fixed sleeps, only web-first assertions and role/label locators (no CSS selectors, no test ids unless the plan justifies one).

### Scenarios (the whole list, keep it small)

- [ ] **Escape layers (finding from 007_02).** In a native dialog (Update category as ADMIN) with a disabled control showing its reason: the first Escape closes only the reason, focus does not move, the second Escape closes the dialog. Same for the row menu as VIEWER. This is the check jsdom could not make.
- [ ] **Reason placement (007_02).** As VIEWER, the reason of a disabled control is visible on hover and on keyboard focus at both viewports, stays inside the viewport, is not clipped by the table scroll region or the New movement drawer, and does not cover its control.
- [ ] **One reason at a time.** Document the known limitation from 007_02 (two reasons can be open at once): either a test that shows the current behaviour and is marked so it is easy to change, or, if the fix is a few lines in `Button`, fix it here and test it. The plan chooses and says why.
- [ ] **Role switching in a real browser.** On Products with a selection, switch ADMIN to VIEWER and back: bulk bar, row menu and count follow without a reload and without refetching the list (assert on network requests).
- [ ] **Core flows, one per mutation, as the role that may do it:** archive products (ADMIN), create a movement then Undo from the toast (CLERK), cancel an order (CLERK) with the status, toast and list reflecting it. Each ends by checking the visible result, not an internal state.
- [ ] **Denied flows:** a VIEWER cannot start any of the three above; the controls are disabled, the reason is reachable by keyboard, and no mutating request leaves the browser.
- [ ] **Virtualized lists:** Movements and Audit log render only a window of rows, scrolling to the end loads the next page once, the focused Copy ID button survives scrolling, and `?mock=slow` and `?mock=error` then Retry behave.
- [ ] **Keyboard path:** a full keyboard-only pass through the shell (skip link, sidebar, role switcher, a page's main action) with a visible focus indicator at each step.

### Accessibility in the browser

- [ ] axe (`@axe-core/playwright`) on every route (Dashboard, Products, Movements, Orders, Order detail, Audit log), at 375 and 1280 px, for each of the three roles on at least the screens with guarded controls, and in the loading, empty and error scenarios of the list screens. Zero violations is the rule; an exception needs an inline comment with the rule id, the reason and an owner-visible TODO, and is listed in the PR.
- [ ] A check for horizontal page scroll at 375 px on every route (document width equals viewport width).

### Gate

- [ ] `pnpm e2e` is green locally, run at least twice in a row to show it is not flaky; the plan reports the duration. `pnpm build`, `lint`, `typecheck`, `test` and `build-storybook` stay green and unchanged.
- [ ] No CI in this feature (phase 3). The PR evidence is the local `pnpm e2e` output.

## Decisions

1. **Small and targeted.** E2E covers what jsdom cannot: native dialog, focus, real layout, service worker, scrolling. Anything already proven well in a component test is not repeated here.
2. **Run against the production build,** because that is what gets deployed.
3. **One browser, two viewports.** Cross-browser is not worth the maintenance for this project; Safari touch behaviour stays a documented manual check.
4. **No new libraries beyond the two named, and only after approval.**
5. **Not in `pnpm test`.** E2E is its own command so the unit gate stays fast.

## Does not include

- CI, Docker, deploy (phase 3 and the deploy step), visual regression or screenshot comparison, performance measurement (the README feature), Firefox and WebKit projects.
- New application behaviour, except the small `Button` fix if the plan chooses it for the "one reason at a time" scenario.

## Notes

- Locators: `getByRole`, `getByLabel`, `getByText`. If a scenario needs a test id, say why in the plan.
- Reset the mock store between tests the cheapest way that works with the service worker (a fresh page context usually does); state the choice in the plan.
- The README feature that follows will cite the e2e and axe results, so keep the output readable.
